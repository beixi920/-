# 04 水墨画风指南：怎么做出「同款水墨汉字」的感觉

> 30 天作业版：桌面浏览器里把 375×667 的竖屏画面等比放大；画风 P0 放在 Day 24，P1 放在 Day 25。

> 目标：**视觉语言一致，素材全部原创**。
> 你可以做到「一眼看上去就是那个味道」，但不能直接使用原作的截图、字体文件、UI 像素、Logo、名称和素材。

## 一、先划清边界：什么能「一样」，什么不能

| 可以一样 | 不能一样 |
|---|---|
| 视觉语言：汉字当单位、水墨笔触、宣纸底、朱砂印章、极简留白 | 原作的具体画面、角色形象、UI 排版像素级复制 |
| 动效思路：字变形、墨点爆开、屏震、满屏技能 | 原作的动画逐帧、特效素材、音效文件 |
| 配色关系：纸白 + 墨黑 + 朱砂 + 少量金 | 直接吸色并逐像素临摹 |
| 字体气质：楷体/宋体/手写感 | 使用原作内嵌字体文件（这是侵权高发区） |
| 玩法机制（见 02 文档） | 游戏名称「赵云与阿斗」、Logo、宣传语 |

> 法律常识：**风格（style）本身通常不受著作权保护，但具体的画、字、角色、界面、素材受保护**。所以「同款画风」的正确做法是：拆解它的视觉规则，用你自己的素材重新实现。这也是为什么原作 3–5 人就能做出来——它的美术成本极低，靠的是「规则」而不是「画」。

## 二、原作画风拆解（基于公开资料）

| 视觉元素 | 原作做法（考证） | 你的实现 |
|---|---|---|
| 单位 | **汉字本身就是单位**：刀、枪、弓、骑、卒、将、斗 | 用同一套字库，字即角色，不做立绘 |
| 状态 | 平时是**静止的字**；进入战斗范围后通过**字体变形**变成战斗形态 | 用 scale/skew/rotate/描边变化做「字在动」 |
| 笔触 | 水墨、书法感、飞白 | Canvas 多重描边 + 随机偏移 + 墨点 |
| 底色 | 宣纸/米黄，低饱和 | 程序化纸张纹理（见第四节） |
| 强调色 | 朱砂红（印章、血量）、少量金（高品质） | 严格 60/30/10 配色 |
| UI | 极简，没有花哨面板 | 印章按钮 + 纸签面板 + 细墨线 |
| 技能 | 满屏墨迹/字阵/笔锋 | 全屏 ink wash + 字阵 + 粒子 |
| 留白 | 大量空白，字距大 | 宁可少画，不要填满 |

**一句话总结风格**：`宣纸的暖白 + 墨的浓淡 + 朱砂的一点红 + 汉字的形变`。

## 三、视觉规范

### 3.1 色彩（先定死，不要临时加色）

| 名称 | Hex | 用途 | 占比 |
|---|---|---|---|
| 宣纸 | `#F3EBD9` | 背景、面板 | 60% |
| 纸暗部 | `#E4D6BC` | 分隔、阴影、暗角 | — |
| 墨黑 | `#1C1914` | 单位字、主文字、笔触 | 25% |
| 淡墨 | `#4B453B` | 次级文字、辅助线 | 5% |
| 朱砂 | `#B23A2B` | 血量、印章、危险提示 | 6% |
| 朱砂亮 | `#D4674F` | 受击闪、强调 | — |
| 金 | `#C9A227` | Lv5、金品质、结算高光 | 3% |
| 紫 | `#8E6BB8` | 紫色品质武将边框、道具稀有度 | 1% |
| 青 | `#4A6F63` | 绿格、极少量的冷色平衡 | 1% |

规则：
- **不要纯黑 `#000`**，用墨黑；不要纯白 `#FFF`。
- **不要渐变大面积铺色**，纸的质感靠噪点，不靠渐变。
- 朱砂只用在「命、印、危险」，一屏红色面积不超过 10%。

### 3.2 字体

**系统字体栈（MVP 直接用，零成本）：**

```css
font-family: "KaiTi", "STKaiti", "Kaiti SC", "Songti SC", "SimSun", "Noto Serif SC", serif;
```

- Windows 有 `KaiTi`（楷体）、`SimSun`（宋体）；macOS 有 `STKaiti`、`Songti SC`；Android 可能落到 `Noto Serif SC`。
- 楷体更像「手写/书法」，宋体更像「古籍印刷」。**原作偏楷/手写感，优先楷体**。

**免费商用字体（想更统一时用）：**

| 字体 | 许可 | 适合 | 注意 |
|---|---|---|---|
| 思源宋体 Source Han Serif SC | SIL OFL 1.1 | 正文、HUD、标题 | 全量包很大，要子集化 |
| 霞鹜文楷 LXGW WenKai | SIL OFL 1.1 | 单位字、标题，手写楷体感强 | 推荐，但同样要子集 |
| 站酷系列（如站酷高端黑） | 官网标注免费商用 | 现代标题 | 每款条款不同，用前查官网 |
| 系统楷体/宋体 | 随系统 | MVP | 不要打包分发字体文件 |

> **字体子集化**：游戏只需要约 100–300 个汉字（刀枪弓骑卒将斗赵关张飞黄忠…），可以用 `fonttools` 的 `pyftsubset` 把 woff2 压到 100–300KB。不会做也没关系：MVP 先用系统字体，等画面稳定后再换。
> **绝对不要**从原作 APK/小游戏包里提取字体文件。

字号层级（设计宽 750）：

| 元素 | 字号 | 字重 | 说明 |
|---|---|---|---|
| 标题 | 56–64 | 700 | 字距 +2 |
| 战场单位字 | 64–80 | 700 | 随等级略增大 |
| HUD 数字 | 28–32 | 700 | 用衬线数字 |
| 说明文字 | 20–22 | 400 | 淡墨色 |
| 伤害飘字 | 22–26 | 700 | 朱砂/墨色，快速上飘 |

### 3.3 纸张质感（三层配方）

不要用一张网图当背景（来源不明 + 体积大），**用 Canvas 程序化生成**：

1. **底色**：`#F3EBD9` 平涂。
2. **噪点**：1–2 万个小点，透明度 0.015–0.05，颜色偏褐。
3. **纤维**：40–60 条极淡的短线，随机角度。
4. **水渍/暗角**：几个大半径径向渐变（透明度 0.03–0.08），四角压暗。

```js
function makePaper(w, h) {
  const c = document.createElement('canvas');
  c.width = w; c.height = h;
  const g = c.getContext('2d');

  g.fillStyle = '#F3EBD9';
  g.fillRect(0, 0, w, h);

  // 水渍
  for (let i = 0; i < 6; i++) {
    const x = Math.random() * w, y = Math.random() * h, r = 60 + Math.random() * 140;
    const rg = g.createRadialGradient(x, y, 0, x, y, r);
    rg.addColorStop(0, 'rgba(150,120,70,0.05)');
    rg.addColorStop(1, 'rgba(150,120,70,0)');
    g.fillStyle = rg;
    g.fillRect(x - r, y - r, r * 2, r * 2);
  }

  // 噪点
  for (let i = 0; i < 12000; i++) {
    g.fillStyle = 'rgba(60,50,35,' + (0.015 + Math.random() * 0.03) + ')';
    g.fillRect(Math.random() * w, Math.random() * h, 1, 1);
  }

  // 纤维
  g.strokeStyle = 'rgba(90,75,55,0.05)';
  g.lineWidth = 1;
  for (let i = 0; i < 50; i++) {
    const x = Math.random() * w, y = Math.random() * h;
    const a = Math.random() * Math.PI, l = 20 + Math.random() * 80;
    g.beginPath();
    g.moveTo(x, y);
    g.lineTo(x + Math.cos(a) * l, y + Math.sin(a) * l);
    g.stroke();
  }

  // 暗角
  const v = g.createRadialGradient(w / 2, h / 2, h * 0.35, w / 2, h / 2, h * 0.85);
  v.addColorStop(0, 'rgba(0,0,0,0)');
  v.addColorStop(1, 'rgba(60,45,25,0.16)');
  g.fillStyle = v;
  g.fillRect(0, 0, w, h);

  return c;
}
```

> 只生成一次，存成离屏 canvas，每帧 `drawImage` 贴上去。**不要每帧重新生成噪点**。

### 3.4 墨迹与笔锋（五个小函数就够）

1. **浓淡线**：同一条路径画 3 遍，线宽 10→6→2，透明度 0.1→0.2→0.5，端点圆头。
2. **飞白**：画完线后，用「纸色小段」盖掉一部分，形成干笔效果（或者用 `destination-out` 擦）。
3. **墨点**：随机半径 1–6px 的圆，透明度 0.1–0.6，带重力下落。
4. **晕染**：径向渐变圆，从 `rgba(28,25,20,0.25)` 到透明，压扁成椭圆。
5. **印章**：朱砂圆角方 + 白字/阴文，随机旋转 ±2°。

```js
function brushLine(ctx, pts, width) {
  for (let k = 0; k < 3; k++) {
    ctx.beginPath();
    for (let i = 0; i < pts.length; i++) {
      const p = pts[i];
      const jx = (Math.random() - 0.5) * 3;
      const jy = (Math.random() - 0.5) * 3;
      i ? ctx.lineTo(p.x + jx, p.y + jy) : ctx.moveTo(p.x + jx, p.y + jy);
    }
    ctx.lineCap = 'round';
    ctx.lineJoin = 'round';
    ctx.lineWidth = width * (1 - k * 0.35);
    ctx.strokeStyle = 'rgba(28,25,20,' + (0.12 + k * 0.16) + ')';
    ctx.stroke();
  }
}

function inkBurst(x, y, n) {
  for (let i = 0; i < n; i++) {
    const a = Math.random() * Math.PI * 2;
    const s = 40 + Math.random() * 160;
    particles.push({
      x, y,
      vx: Math.cos(a) * s,
      vy: Math.sin(a) * s - 40,
      r: 1 + Math.random() * 5,
      life: 0.4 + Math.random() * 0.4,
      max: 0.8
    });
  }
}
```

### 3.5 单位渲染结构

每个单位从下到上画 4 层：

```
① 墨晕底（椭圆，径向渐变，表示"落"在纸上）
② 汉字本体（预渲染缓存，**纸色 ~3px 外圈留白 + 墨色填充**）
③ 受击/攻击形变（整体 transform，不重绘字）
④ 左上角等级数字角标（离屏预渲染，唯一的等级视觉）
```

> **实现口径（Day 24 验收修订）**：本文初版的「2–3px 墨色描边」是按 demo 里 74px 大字写的；游戏内单位字只有 24–26px，**字号小的时候不要用 2.5px 墨边**——700 字重的墨字再描一圈 2.5px 墨边会糊成一团。实际实现改为：楷体 400 字重 + 纸色 3.2px 外圈 + 墨色/朱砂色填充，字周围留一圈纸色，笔画清楚且不粘格线；高分屏的缓存 canvas 按 DPR 放大再缩回。

> **实现口径（Day 26 补丁）**：**等级环（1–2 墨环 / 3–4 朱砂环 / 5 金双环）与字下方等级点已整体删除**，`art.rank` 配置段与 `render.js` 的 `drawRankRing()` 一并移除。等级视觉只剩左上角 15px 数字角标，参数在 `art.figure.badge*`。**弓 / 刀的武器形态同样不带环和点，但保留角标**；阿斗红心、武将金 / 紫品质边框、技能 CD 环、敌方血条、休眠单字金虚线框全部保持原样。

等级视觉规则（只看角标）：

| 等级 | 角标数字与边框 | 额外 |
|---|---|---|
| 1–2 | 墨色 `#1C1914` | 无 |
| 3–4 | 朱砂 `#B23A2B` | 无 |
| 5 | 金色 `#C9A227` | 数字下方一条 6×2px 小金线（数字上移 1px 让位） |

### 3.6 动效规范（照这个表做就不飘）

| 动作 | 时长 | 缓动 | 形变 |
|---|---|---|---|
| 待机 | 2.4s 循环 | sine | 上下 1.5px，缩放 1.00–1.02 |
| 刀攻击 | 0.28s | 先快后慢 | 旋转 -22°→+8°，前冲 6px |
| 枪攻击 | 0.25s | ease-out | 前刺 18px，横向拉伸 1.15 |
| 弓攻击 | 0.35s | ease-in-out | 横向压扁 0.82（拉弓）→ 回弹，箭飞出 |
| 骑攻击 | 0.30s | ease-out | 前冲 12px + 后仰 -8°，2 个残影 |
| 受击 | 0.15s | linear | 闪白 + 抖动 3px |
| 合成 | 0.45s | 弹性 | 两字靠拢 → 放大 1.6 → 墨点爆开 → 新字落下 |
| 阿斗受击 | 0.40s | 衰减 | 全屏震 8px + 朱砂闪边 |
| 武将技能 | 0.8–1.2s | 分段 | 全屏墨wash + 字阵 + 笔锋线 |
| 结算 | 0.35s | ease-out | 纸卷从下往上展开 |

> 关键：**字不要整块乱飞**。攻击是「形变」，不是「位移到敌人身上」；远程才发弹道。这样才有「字在打架」而不是「图标在飞」。

> 实现口径（Day 25 修订）：上表是视觉意图，具体数值一律以 `data/balance.js` 的 `art.anim` 为准——四种攻击的前冲统一压到 **0.1 格**（`dashCells`），刀是 **±0.2 弧度摆动且末段快速回正**（不是 -22°→+8° 的单向转），枪 **scaleX 1.25**，弓 **0.82→1 回弹 + 箭从字上飞出**（真正的弹道由 combat 的 projectile 发），骑是 **2 帧半透明拖影、不叠粒子**。美术调参只改 `art.anim`，别改回像素级大位移。

> 实现口径（Day 26 字形变）：字主体仍守上一段的 0.1 格上限，**武器单独前伸**（枪头 0.35 格、枪杆 1.2×）；枪 / 骑在 `src/weapon-art.js` 用 Canvas 路径手绘，参数在 `art.weapon`——枪杆＋三角头带 2–4 个贯穿墨点、方天画戟抡 300° 带 3 道圆弧残影（半径按 `splashRadius` 换算）；**刀已于 Day 26 续 3 改为「拆层抡刀」，旧月牙刃参数 `art.weapon.blade` 与 `weapon-art.js blade()` 作废**。枪 / 骑的**动画时长 = min(0.35s, 单位 `intervalSec` × 0.7)**，高等级攻速快自动加快、不拖拍；命中墨点由「敌人掉血跳变」统一触发，复用 72 槽粒子池。以上全部只读状态，伤害 / 命中 / CD / 波次一行未动。

> 实现口径（Day 26 续 · 弓 v2）：弓单独一套 **0.5s 阶段动画**，实现在 `src/weapon-fx.js`（`render.js` 接近 800 行硬上限，不再往里加），参数在 `art.weapon.bow`——① 0–0.08s「弓」字淡出缩小轻旋 + 墨点爆开、弓形淡入（用 `morphSwap` 严格互斥，不同时出现）；② 0.08–0.12s 弓转向开火瞬间锁定的敌人；③ 0.12–0.22s 拉 V 弦、搭箭；④ 0.22–0.25s 弦回弹、弓身后坐、箭离弦；⑤ 到 0.38s 箭飞到弹道终点（目标死亡/漏掉也飞到最后已知位置再消散）+ 命中闪白与墨爆；⑥ 0.40–0.50s 弓先淡出、字再淡入，结束无残影。**弓的时长 = min(0.5s, `intervalSec` × 0.85)**，各阶段按 `T = k × nominalSec` 等比压缩，连射不拖拍。箭的视觉接管 `combat` 的 projectile（`_bowDriven` 表现标记避免画两支），伤害结算仍由逻辑层负责。别把弓改回「字上叠武器」的旧画法。

> 实现口径（Day 26 续 2 · 弓 v3，**取代 v2 的第 ⑥ 段**）：单位加 `stance: 'glyph' | 'weapon'` 与 `lastAttackAt`（纯表现，逻辑层不读）。持续攻击时**弓形态常驻**：只有从 glyph 起步时播一次 0.08s 字变弓；已在 weapon 的每箭只播 瞄准 → 拉弦 → 放箭 → 箭飞行，箭与箭之间是「搭箭待发」的弓（`idlePull` 轻拉弦 + 待发箭），**不再每箭变回字**。停火 ≥ `art.weapon.idleHoldSec`（1.2s）才播 0.15s 回归过渡（弓淡出、字淡入，`returnSwapSec` 互斥）落回 glyph；期间每次开火都重新锁定目标角度，弓当前角度用 `turnSec` 平滑插值转过去。weapon 状态下等级环保留、**字与等级点隐藏**；暂停 / 结算 / 重开 / 升级强制回 glyph 并清过渡。阶段终点仍用 `art.weapon.bow` 的 0.5s 标称时间轴（删掉了 v2 的 `returnStart` / `returnSwap`），时长仍 = min(0.5s, `intervalSec` × 0.85)，伤害 / CD / 判定一行未动。

> 实现口径（Day 26 续 3 · 刀「拆层抡刀」，已完成）：`art.weapon.dao.strokePolygon` 是**字框 0~1 比例**的 10 点多边形（字框 = 字号 em 方框，居中在 `art.glyph.cacheSize` 的 96px 缓存里），起点向右上延伸把撇的起笔连同纸色外圈一起罩住；`pivot (0.46,0.13)` 是起笔旋转轴。拆层在 **`cacheScale` 3 倍字号**的 288×288 离屏缓存上做，用带符号距离的软遮罩（`featherPx 0.5` 羽化）分成 `静止层`（多边形内 alpha 归零，**不留任何撇痕**）与 `挥动层`（只留左撇），再缩回 96px 逻辑尺寸——26px 直接切多边形的台阶锯齿由高倍缩小天然抗锯齿掉。绘制全在 `src/weapon-fx.js`（`render.js` 只留 4 行分流）。
>
> 静止时直接画整字（不叠两层，避免羽化边界出现浅色缝）；每次攻击按 `state.elapsed - u._fireAt` 播一段 **min(0.30s, 攻击间隔 × 0.8)**：起势 0–0.08s 抬 −15° → 抡刀 0.08–0.18s ease-out 扫到 +35° → 回正 0.18–0.28s 过冲 −3° 后归 0°。**整字（横折钩）全程不动，只有撇层绕轴转**，方向固定左上→右下、不读敌我坐标；每次攻击只留 **1 道**同款撇残影（透明度 0.10→0、0.10s、角度落后 5°），不加刀光 / 粒子，命中反馈沿用受击闪白与墨点。调试高亮 `debug.enabled` 验收后已关（0）。判定 / 数值 / CD / 波次一行未动。

> 实现口径（Day 26 续 4 v4 · 枪「木变枪」姿态状态机，**取代上一版逐枪变回整字**）：`art.weapon.qiang.muPolygon` 仍是 12 点逐行折线（覆盖率 39.6%，静止层木残留 0 / 挥动层切仓 0），拆层在 3× 离屏缓存 + 0.5px 羽化软遮罩上做，缩回 96px 无台阶。单位用和弓一致的 `stance: 'glyph' | 'weapon'` + `lastAttackAt`（纯表现，逻辑层不读）：从 glyph 第一次开火播 **0.07s「木变枪」**——木从原位抬到单位中心、沿竖轴拉成 `spearLen 1.55` 的枪杆、按 `aim.angle + 90°` 转向目标、顶端 12% 小三角枪头淡入，**仓全程不动**；weapon 期间每枪只播 **瞄准（0~22%）→ 前刺（~58%）→ 收回待发**，两次攻击之间保持枪形、枪尖按 `turnSec 0.12s` 平滑追当前目标（60ms 节流），不再闪回整字。停火 ≥ `idleHoldSec 1.2s` 播 **0.15s「枪变回木」**（枪层淡出、整字淡入的交叉淡化），再来敌重新变形。前刺沿锁定方向前移 `extendCells 0.25` 格、枪杆额外 1.15×，真穿透多敌时沿线点 3 个 α≤0.42 / r=1.6px 淡墨点；每次攻击只留 **1 道** α 0.09→0、0.10s 枪影。绘制在 `src/qiang-fx.js`（枪从 `weapon-fx.js` 按职责拆出，共享 `Game.weaponFx.split` 拆层管线），`render.js` 只留 3 行分流 + `animSec` 枪分支 + 首帧 `_lastCd=0`。**握把轴 `pivot 0.70`**：不能绕木中心转（木在字框左缘，转 180° 会整块甩到仓那边），成形时锚点再从木原位插值到格中心。暂停 / 结算 / 重开 / 升级强制回 glyph。旧 `turnRatio/maxTurnDeg` 是 v3 口径已作废，`art.weapon.spear` / `weapon-art.js spear()` 保留但不再调用；判定 / 数值 / CD / 波次一行未动。

### 3.7 UI 规范

- **按钮 = 印章**：朱砂底、白字、2px 墨边；按下时 `translateY(2px)`。
- **倾斜规则（避免「歪得乱」）**：孤立的印章类主按钮（开始游戏、印章装饰）可以倾斜 **-1°~-2°**；**成排或功能性按钮（征兵、暂停、菜单、结算、设置）一律 0°，同一组角度必须一致**。歪只用于「孤立的印」，不用于「成排的按钮」。
- **面板 = 纸签**：纸色底、细墨边（1–2px）、轻微不规则边（CSS `clip-path` 多边形）、不要圆角卡片。
- **血条**：阿斗用红心；来袭敌兵用贴「格子上沿」的细红条（按 hp/maxHp）。

> 实现口径（Day 25 续 2 修订）：敌方字下 3 颗朱砂点已去掉（会和字、血条挤在一起），血量统一由格子上沿的细红条表示。3.7 原来的「3 颗朱砂点」是早期草案，别照它改回去。棋盘中间是城墙带而不是波浪线；格子铺满整格、只留 1px 格缝，圆角 2–3px、左上亮 / 右下暗的轻浮雕。**等级点已于 Day 26 补丁整体删除**，单位只保留左上角数字角标。
- **备战席**：5 个纸签格子，拖拽时轻微倾斜。卡面只有两种：兵/字卡写汉字，**铲子卡画图标**（`src/bench-art.js` 程序化 Canvas，不引图片）——短木柄 `#C98A4B`、深灰铲头 `#7C8792`、粗黑描边约 2px、底部一道淡阴影，尺寸约卡面的 66%；拖影复用同一张图标（34px）。界面上不再有「铲 ×N」计数。

- **数字**：全部用衬线数字，不要用无衬线。

### 3.11 棋盘地形（实现口径，Day 25 起）

- 地形全部由 `src/board-art.js` 程序化生成，**只生成一次**存成离屏 canvas，之后每帧只 `drawImage`；被铲开的 D 格由同一套 `tile(列,行)` 按需补画，花纹与静态层一致。
- 参数全在 `data/balance.js` 的 `art.board`：草地底 `#8E9A7E` + 噪点 / 外圈草叶、粗石框 `#4C5B4D` 7px、四角朱砂三角；格子铺满整格、1px `rgba(0,0,0,.12)` 格缝、±3% 色抖、圆角 2.5px、左上亮 / 右下暗轻浮雕；五类格配色 `cellP/cellD/cellW/cellR/cellH`。

- 铁律：不逐帧 `fillText`、不逐帧新建 canvas、不用 `shadowBlur`/`filter`（详见 4.2）。

## 四、实现方案（Canvas + DOM）

### 4.1 分层

```
第 0 层：paper（离屏 canvas，生成一次）
第 1 层：board（棋盘线、路径、白/绿格）
第 2 层：units（单位、敌人）
第 3 层：fx（粒子、飘字、技能特效）
第 4 层：UI（DOM：HUD、按钮、备战席、结算）
```

### 4.2 三个性能铁律

1. **汉字预渲染**：每个「字 + 等级」画到离屏 canvas 缓存，每帧只 `drawImage`。
2. **粒子池**：最多 60–80 个，超出复用最旧的；不要每帧 `new`。
3. **少用 `shadowBlur`/`filter`**：它们在中端手机上极慢；用多层半透明描边模拟晕染。

### 4.3 代码骨架

```js
// 1) 预渲染文字
const cache = {};
function getChar(ch, size, color) {
  const key = ch + size + color;
  if (cache[key]) return cache[key];
  const c = document.createElement('canvas');
  c.width = 128; c.height = 128;
  const g = c.getContext('2d');
  g.textAlign = 'center';
  g.textBaseline = 'middle';
  g.font = '700 ' + size + 'px "KaiTi","STKaiti",serif';
  g.lineWidth = 3;
  g.strokeStyle = 'rgba(28,25,20,0.85)';
  g.fillStyle = color;
  g.strokeText(ch, 64, 66);
  g.fillText(ch, 64, 66);
  cache[key] = c;
  return c;
}

// 2) 主循环（固定步长）
let acc = 0, last = performance.now();
const STEP = 1 / 60;
function loop(now) {
  let dt = (now - last) / 1000;
  last = now;
  dt = Math.min(dt, 0.1);
  acc += dt;
  while (acc >= STEP) { update(STEP); acc -= STEP; }
  render();
  requestAnimationFrame(loop);
}
```

## 八、常见误区

| 误区 | 为什么不像 | 正确做法 |
|---|---|---|
| 用纯黑纯白 | 太硬、像 PPT | 墨黑 + 纸白 |
| 字太细 | 没有「碑帖」力量感 | 700 字重 + 描边 |
| 加发光/霓虹 | 和水墨冲突 | 只用墨的浓淡和朱砂 |
| 圆角卡片 + 阴影 | 现代 UI 感 | 纸签 + 细墨线 |
| 满屏特效 | 廉价、卡顿 | 留白 + 关键帧特效 |
| 直接描原作截图 | 侵权且僵硬 | 拆规则，自己实现 |
| 单位用 emoji/图标 | 失去「汉字即角色」 | 全部用字 |

## 九、让 AI 帮你找感觉（但不侵权）

1. **让 AI 生成「文字描述」的 mood board**：例如「宣纸、水墨、朱砂印章、汉字作为棋子、极简、留白」——用文字做参考，不要直接喂原作截图让 AI 仿。
2. **AI 生图只做情绪板**：生成后不要直接放进游戏；检查工具的商用条款。
3. **最稳的做法**：程序化纹理 + 字体排版，既独特又零版权风险。
4. **不要**让 AI「照着这张截图做一个一样的」——产出的图很可能与原作构成实质性相似。
